# 명세 완결성 체크리스트 (A-Specification)

기획서가 충분히 명확하고 완결한지 검증하는 체크리스트입니다.
각 항목에서 **미확정**이 나오면 개발 전에 기획자와 협력해야 합니다.

---

## A-01 경계값 (Boundary Values)

숫자, 길이, 범위의 한계값이 명확한가?

- [ ] **A-01-1**: 입력 필드의 최소/최대 길이가 명시되어 있는가? (예: 이름 1~50자)
- [ ] **A-01-2**: 숫자 입력의 범위가 명시되어 있는가? (예: 나이 1~150세)
- [ ] **A-01-3**: 리스트/테이블의 최대 행 수 제한이 있는가? 무한 스크롤인가?
- [ ] **A-01-4**: 날짜 범위 선택 시 과거/미래 제한이 있는가?
- [ ] **A-01-5**: 파일 업로드 크기/개수 제한이 있는가? (예: 파일당 100MB, 최대 5개)

---

## A-02 빈 값 (Empty/Null Values)

빈 값, null, 미입력 상태를 어떻게 처리하는가?

- [ ] **A-02-1**: 필수 필드와 선택 필드가 명확히 구분되어 있는가?
- [ ] **A-02-2**: 빈 상태를 표시하는 UI가 정의되어 있는가? (예: "데이터 없음", 회색 처리)
- [ ] **A-02-3**: 빈 필드로 검색/필터링하면 어떻게 되는가?
- [ ] **A-02-4**: 선택지 없이 빈 드롭다운/셀렉트박스의 기본값은?
- [ ] **A-02-5**: 조건부 필드(보기 조건)에서 비활성화된 필드는 제출 시 무시되는가?

---

## A-03 예외 문자 (Special Characters)

특수문자, 한글/영문 혼합, 이모지 등의 처리?

- [ ] **A-03-1**: 입력 필드가 받을 수 있는 문자 집합이 명시되어 있는가? (예: 숫자만, 한글+영문+숫자)
- [ ] **A-03-2**: 이모지, 기호(#, @, ?, !, 등)는 허용되는가?
- [ ] **A-03-3**: SQL 인젝션 위험 문자('", <, >, 등)는 어떻게 처리되는가?
- [ ] **A-03-4**: 줄바꿈(\n), 탭(\t) 같은 whitespace 처리가 정의되어 있는가?
- [ ] **A-03-5**: 아라비아 숫자/한글 숫자 혼합 입력 시 정규화되는가?

---

## A-04 상태 조합 (State Combinations)

로그인/비로그인, 세션만료 등 사용자 상태별 동작?

- [ ] **A-04-1**: 로그인하지 않은 사용자가 접근하면 어디로 리디렉션되는가?
- [ ] **A-04-2**: 세션 만료 중 작업 중이면 어떻게 되는가? (저장됨/손실/복구)
- [ ] **A-04-3**: 관리자/일반사용자/손님별로 보이는 UI가 다른가? 각각 정의되어 있는가?
- [ ] **A-04-4**: 동일 계정으로 다중 로그인 시 이전 세션은 종료되는가?
- [ ] **A-04-5**: 권한 변경(예: 일반사용자 → 관리자)이 실시간 반영되는가?

---

## A-05 중복 실행 (Duplicate Execution)

같은 작업을 여러 번 실행하면 어떻게 되는가?

- [ ] **A-05-1**: 버튼을 빠르게 여러 번 클릭하면 중복 요청이 방지되는가?
- [ ] **A-05-2**: 폼을 두 번 제출하면 어떻게 되는가? (중복 생성/무시/경고)
- [ ] **A-05-3**: 뒤로가기 후 다시 진행했을 때 중복 생성 위험은 없는가?
- [ ] **A-05-4**: 결제 같은 중요 작업에서 멱등성(idempotent) 보장 방법이 있는가?
- [ ] **A-05-5**: 네트워크 불안정 시 자동 재시도가 중복을 만들지 않는가?

---

## A-06 조건 결합 (Condition Combinations)

AND, OR 같은 논리 조합이 명확한가?

- [ ] **A-06-1**: 필터링에서 여러 조건을 동시에 적용하는 방식이 명시되어 있는가? (AND/OR)
- [ ] **A-06-2**: 권한 검사에서 모든 권한이 필요한가, 하나만 필요한가? (AND/OR)
- [ ] **A-06-3**: 표시/숨김 조건이 여러 개면 어떻게 결합되는가?
- [ ] **A-06-4**: 입력 검증이 여러 규칙이면 모두 만족해야 하는가?
- [ ] **A-06-5**: 나이+지역 같은 복합 조건의 우선순위나 평가 순서가 정의되어 있는가?

---

## A-07 정렬·순서 (Sorting/Ordering)

항목의 순서는 어떻게 결정되는가?

- [ ] **A-07-1**: 기본 정렬 방식이 명시되어 있는가? (예: 최신순, 인기순, 가나다순)
- [ ] **A-07-2**: 동일한 값이 여러 개면 이차 정렬은? (예: 같은 날짜면 이름순)
- [ ] **A-07-3**: 사용자가 정렬을 변경할 수 있는가? 변경 후 기억되는가?
- [ ] **A-07-4**: 페이지네이션에서 정렬이 유지되는가? (1페이지 최신순 → 2페이지도 최신순)
- [ ] **A-07-5**: 검색 결과의 정렬 기준은? (문자열 매칭 점수? 인기도?)

---

## A-08 에러 처리 (Error Handling)

예상되는 모든 에러 시나리오가 정의되어 있는가?

- [ ] **A-08-1**: 필드 검증 실패 시 메시지가 구체적인가? (예: "10글자 이상이어야 합니다" vs "오류 발생")
- [ ] **A-08-2**: 네트워크 실패 시 재시도 UI가 있는가?
- [ ] **A-08-3**: 서버 에러(500, 503 등)에 대한 사용자 안내가 있는가?
- [ ] **A-08-4**: 권한 없음(403), 없는 리소스(404)에 대한 처리가 각각 정의되어 있는가?
- [ ] **A-08-5**: 예상 불가능한 상황(매우 드문 버그)을 만났을 때 UX는? (에러 로깅, 지원팀 연락)

---

## A-09 상태 유지 (State Persistence)

새로고침/뒤로가기/URL 직접 입력 후 상태는 유지되는가?

- [ ] **A-09-1**: 페이지 새로고침 후 입력한 필드 값이 유지되는가? (로컬스토리지/세션스토리지)
- [ ] **A-09-2**: 필터/정렬 설정이 URL에 반영되는가? (bookmarkable)
- [ ] **A-09-3**: 뒤로가기 후 이전 상태(스크롤, 선택, 입력)가 복원되는가?
- [ ] **A-09-4**: 모달/팝업 닫은 후 뒤로가기하면 모달을 다시 열어야 하는가?
- [ ] **A-09-5**: 탭이 여러 개면 각 탭의 상태가 독립적으로 유지되는가?

---

## A-10 데이터 정합성 (Data Consistency)

여러 곳에 같은 데이터가 표시될 때 동기화되는가?

- [ ] **A-10-1**: 사용자 정보를 수정했을 때 다른 페이지에서도 즉시 반영되는가?
- [ ] **A-10-2**: 목록에서 삭제한 항목이 상세 페이지에서도 삭제된 상태로 보이는가?
- [ ] **A-10-3**: A 사용자가 B 사용자가 편집 중인 문서를 동시에 편집하면? (충돌 처리)
- [ ] **A-10-4**: 캐시가 있다면 데이터 갱신 시점이 명시되어 있는가?
- [ ] **A-10-5**: 오프라인 상태에서 온라인 복귀 시 동기화 전략이 정의되어 있는가?

---

## A-11 문구·표기 (Text/Formatting)

모든 사용자 표시 문구가 확정되어 있는가?

- [ ] **A-11-1**: 에러/경고/성공 메시지의 정확한 문구가 기획서에 적혀 있는가?
- [ ] **A-11-2**: "삭제하시겠습니까?", "정말입니까?" 등의 모달 메시지가 정의되어 있는가?
- [ ] **A-11-3**: 날짜/시간/숫자의 표기 형식이 명시되어 있는가? (예: 2025-01-15 vs 15/01/2025)
- [ ] **A-11-4**: 통화 기호, 소수점 표기가 정의되어 있는가? (예: $1,234.56 vs 1.234,56€)
- [ ] **A-11-5**: 복수형, 단수형 표시가 고려되어 있는가? (예: "1개", "2개" vs "개")

---

## A-12 용어·정의 (Terminology/Definitions)

기획서에서 사용된 용어가 일관되고 명확한가?

- [ ] **A-12-1**: 같은 개념이 다른 말로 불리지는 않는가? (예: 삭제 vs 제거 vs 없음)
- [ ] **A-12-2**: 도메인 용어(비즈니스 용어)의 정의가 명시되어 있는가?
- [ ] **A-12-3**: 약자(API, CSV 등)가 처음 나올 때 풀어서 설명되어 있는가?
- [ ] **A-12-4**: "사용자", "회원", "고객", "운영자" 등의 역할이 명확히 구분되는가?
- [ ] **A-12-5**: 시간 단위(초, 분, 시간, 일)가 일관되게 사용되는가? (예: "3시간 내" vs "180분 이내")

## A-13 상호작용 메커니즘 (Interaction Mechanism)

버튼/링크처럼 액션을 유발하는 요소에 최우선으로 적용한다.
"~한다"라고만 쓰여 있고 결과가 화면에 어떻게 나타나는지가 없으면 전부 이 항목의 갭이다.

- [ ] **A-13-1**: 액션의 결과가 어떤 방식으로 나타나는가? (새 페이지 이동 / 모달 팝업 / 레이어 팝업 / 같은 화면 안에서 인라인 갱신 / 새 탭)
- [ ] **A-13-2**: 미디어(영상 등) 재생이라면: 자동재생인가 사용자 조작이 필요한가? 임베디드(같은 화면 안)인가 별도 플레이어/새 창인가?
- [ ] **A-13-3**: 전환에 로딩이나 트랜지션이 있는가, 즉시 전환되는가?
- [ ] **A-13-4**: 닫기/뒤로가기 시 어느 화면으로 돌아가는가?

**예시 (재생 버튼)**: "클릭 시 재생을 시작한다"라고만 쓰여 있으면 —
- "레이어 팝업으로 열리나요?"
- "같은 화면에서 인라인으로 재생되나요?"
- "진입 시 자동재생인가요?"

를 각각 별도 질의로 만든다.

## 판정 원칙

명세 갭(specification gap)을 판단하는 기준입니다.

### 원칙 1: 개발자 해석 편차
**"개발자 3명에게 물었을 때 답이 갈릴 여지가 있으면 명세 갭이다."**

- 같은 기획서를 읽어도 구현 방식이 다를 수 있다 → 명세 부족
- 예시:
  - 기획서: "빠르게 로딩한다" → 몇 초? (1초? 3초? 5초?)
  - 기획서: "큰 순서대로 표시한다" → 내림차순? 정렬 기준은?
  - 기획서: "사용자가 원할 때" → UI 버튼? 자동? 설정?

### 원칙 2: 검증 불가능한 명세
**"명세가 있어도 검증 불가능하면("적절히", "빠르게") 갭이다."**

- 정량적이지 않으면 테스트할 수 없다 → 명세 개선 필요
- 금지된 표현:
  - "적절한", "적절히"
  - "빠르게", "충분히", "적당히"
  - "자연스럽게", "좋게", "예쁘게"
  - "일반적으로", "보통", "대부분"
- 대신 구체적으로:
  - "3초 내" (정량)
  - "400px 미만일 때" (정량)
  - "버튼 클릭 후 서버 응답까지 총 2초 이내" (측정 가능)

### 원칙 3: 창작 금지
**"기획서에 없는 동작을 창작하지 말고 질의로 배출한다."**

- 개발자가 "이렇게 하면 좋을 것 같은데"는 구현하지 않음
- 명세에 없으면 모두 질의서로 올린다
- 예시:
  - 기획서에 "검색 기능" only → 자동완성, 최근 검색어 등은 별도 질의 필요
  - 기획서에 "삭제 버튼" only → 삭제 확인 모달 필요 여부를 물어야 함
  - 기획서에 "내 정보 수정" only → 수정 후 어디로 이동? 뒤로? 홈? 같은 페이지?

## 체크리스트 사용법

### 기획서 검수 단계

1. 위 A-01 ~ A-13의 모든 체크항목을 기획서 대비하여 검토
2. **미확정** 항목마다 구체적인 질의서 생성
3. 개발 시작 전 모든 미확정을 **확정**으로 변경

### 결과 기록

```
| 분류 | 항목 | 상태 | 비고 |
|------|------|------|------|
| A-01 | A-01-1 | ✓ 확정 | 이름 2~50자 명시됨 |
| A-01 | A-01-2 | ⚠️ 미확정 | 나이 범위 범위 미명시 → 질의#42 |
| A-04 | A-04-1 | ✓ 확정 | 비로그인 시 로그인 페이지로 리디렉션 |
```
