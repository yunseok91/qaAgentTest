# UX·접근성 체크리스트 (B-UX/A11y)

기획 단계에서 **확정되지 않으면 개발을 시작할 수 없는** 접근성과 UX 항목들을 검증합니다.
기준: KWCAG 2.2 (KS X OT0003:2022, 4원칙·14지침·33검사항목) + Nielsen 휴리스틱 + 영상 스트리밍 특화

---

## 핵심 접근성 (Accessibility)

### KWCAG 2.2 필수 항목

| 검사항목 | 기획서 확인 항목 | 미확정 시 리스크 | 상태 |
|---------|-----------------|-----------------|------|
| **5.2.1 자막 제공** | 영상에 한국어 자막이 필수 제공되는가? | 청각장애인 접근 불가 | ○ / ✗ / ● / - |
| **5.4.2 자동재생 소리** | 음성/음악이 자동 재생되는가? 사용자 동의가 선행되는가? | 청각장애인 편의성, 일반 사용자 방해 | ○ / ✗ / ● / - |
| **6.2.2 자동전환 정지** | 콘텐츠가 자동으로 전환되면(슬라이드쇼, 자동재생) 멈추기 버튼이 있는가? | 물리적 어려움이 있는 사용자의 읽을 시간 부족 | ○ / ✗ / ● / - |
| **6.5.1 단일 포인터 조작** | 스와이프/핀치 필수 조작이 있는가? 대안(버튼)이 있는가? | 손가락 근력 약화 사용자 접근 불가 | ○ / ✗ / ● / - |
| **6.1.1 키보드/리모컨 조작** | 마우스 없이 키보드만으로 모든 기능 조작이 가능한가? | 신체장애인, 리모컨-TV 환경 사용 불가 | ○ / ✗ / ● / - |
| **6.1.2 포커스 표시** | 탭으로 이동할 때 현재 포커스된 요소가 시각적으로 표시되는가? (테두리, 밑줄 등) | 키보드 사용자 길을 잃음 | ○ / ✗ / ● / - |
| **6.2.1 세션 만료** | 세션 만료 전에 사용자에게 알림을 주는가? (예: 2분 내 자동 로그아웃) | 작업 중 갑자기 로그아웃 → 손실 | ○ / ✗ / ● / - |
| **6.4.3 링크 텍스트** | 링크 텍스트가 목적을 명확히 하는가? ("더보기" X → "개인정보 정책 보기" O) | 스크린리더 사용자가 링크 목적 불명확 | ○ / ✗ / ● / - |
| **7.2.1 의도치 않은 새 창/자동실행** | 새 창 열림이나 미디어 자동 실행이 필요한가? 필요하면 기획서에 명시되어 있는가? | 사용자가 예상 못하고 혼란 | ○ / ✗ / ● / - |
| **7.3.1 오류 정정** | 입력 오류가 발생했을 때 오류 항목과 정정 방법이 명확한가? | 사용자가 어디서 잘못했는지 모름 | ○ / ✗ / ● / - |
| **7.3.2 레이블** | 모든 입력 필드에 `<label>` 텍스트가 있는가? (placeholder만 사용 X) | 스크린리더가 필드 목적 읽지 못함 | ○ / ✗ / ● / - |
| **7.3.3 접근 가능한 인증** | 로그인 시 CAPTCHA만 사용되는가? 음성 CAPTCHA/이미지 텍스트 옵션이 있는가? | 시각/청각장애인 로그인 불가 | ○ / ✗ / ● / - |
| **5.1.1 아이콘 버튼 대체 텍스트** | 텍스트 없는 아이콘(🔍, ❤️, ⋯)에 aria-label이 있는가? | 스크린리더 사용자가 버튼 목적 불명확 | ○ / ✗ / ● / - |
| **5.4.3 명도 대비** | 텍스트와 배경의 명도 대비가 4.5:1 이상인가? (작은 텍스트 3:1 최소) | 저시력 사용자가 텍스트 읽기 어려움 | ○ / ✗ / ● / - |

### 판정 기준

- **✗ 위반** (Violation): 기획서에 명시적으로 접근성을 **위반하는** 내용이 적혀 있는 경우만  
  (예: "CAPTCHA만 사용한다", "아이콘만 표시, 텍스트 없음")
- **○ 미확정** (Unresolved): 기획서에 언급이 **없는 경우** ← 개발 전에 확정 필요
- **● 준수** (Compliant): 기획서에 접근성을 고려한 내용이 명시된 경우
- **-** (N/A): 해당 기능이 없는 경우 (예: 영상 없음 → 5.2.1 해당 없음)

## Nielsen 휴리스틱 원칙

사용성(UX)의 10가지 휴리스틱 원칙. 기획 단계에서 각 원칙이 고려되었는지 확인합니다.

| 휴리스틱 | 확인 항목 | 상태 |
|---------|----------|------|
| **1. 시스템 상태 가시성** | 현재 상태(로딩, 완료, 에러)가 UI에 명확히 표시되는가? (예: 로딩 스피너, "저장됨" 메시지) | ✓ / ⚠ / ✗ |
| **2. 시스템과 현실의 일치** | 기술 용어 대신 사용자가 아는 말을 쓰는가? (예: "캐시 초기화" X → "임시 데이터 삭제" O) | ✓ / ⚠ / ✗ |
| **3. 사용자 제어와 자유** | "실행 취소", "뒤로가기", "다시" 같은 복구 기능이 있는가? 버튼 누르기 쉽게 배치되어 있는가? | ✓ / ⚠ / ✗ |
| **4. 시스템 일관성** | 버튼, 색상, 용어, 동작이 전체 서비스에서 일관되는가? | ✓ / ⚠ / ✗ |
| **5. 에러 방지** | 위험한 작업(삭제, 결제) 전에 확인 단계가 있는가? 실행 취소 가능한가? | ✓ / ⚠ / ✗ |
| **6. 도움말·문서** | 사용자가 도움말을 찾기 쉬운가? FAQ, 가이드, 콘텍스트 도움말이 충분한가? | ✓ / ⚠ / ✗ |
| **7. 유연성과 효율성** | 숙련된 사용자를 위한 단축키나 빠른 경로가 있는가? | ✓ / ⚠ / ✗ |
| **8. 미니멀한 디자인** | 불필요한 정보가 많지는 않은가? 가장 중요한 것부터 표시되는가? | ✓ / ⚠ / ✗ |
| **9. 에러 복구** | 에러 메시지가 문제와 해결법을 명확히 제시하는가? (예: "비밀번호 8자 이상 필요" vs "오류 발생") | ✓ / ⚠ / ✗ |
| **10. 즉각적 피드백** | 사용자 작업에 대한 반응이 지체되지 않는가? (로딩 > 0.5초면 피드백 필요) | ✓ / ⚠ / ✗ |

### 판정

- **✓ 준수**: 기획서에 원칙이 충분히 고려되어 있음
- **⚠ 부분 준수**: 일부만 고려되어 있음 → 보완 필요
- **✗ 미준수**: 기획서에 언급 없음 → 개발 전에 협력 필요

## 영상 스트리밍 특화

동영상 콘텐츠 서비스(넷플릭스, 유튜브, OTT 플랫폼 등)에 필수적인 항목들입니다.

### 자막·더빙

| 항목 | 기획서 확인 | 상태 |
|------|-----------|------|
| **한국어 자막 제공** | 모든 영상에 한국어 자막이 기본 제공되는가? | ○ / ✗ / ● / - |
| **외국어 자막** | 영어, 중국어 등 외국어 자막 제공 계획이 있는가? | ○ / ✗ / ● / - |
| **자막 크기/스타일 커스터마이징** | 사용자가 자막 크기, 배경, 색상을 바꿀 수 있는가? | ○ / ✗ / ● / - |
| **음성해설(오디오 디스크립션)** | 시각정보 설명 음성 트랙이 있는가? (미포함 시 "없음" 명시) | ○ / ✗ / ● / - |
| **더빙 트랙** | 원본 외에 더빙된 언어 버전이 있는가? 스위칭 UI가 있는가? | ○ / ✗ / ● / - |

### 화질·스트리밍

| 항목 | 기획서 확인 | 상태 |
|------|-----------|------|
| **화질 선택** | 사용자가 480p/720p/1080p 등 화질을 선택할 수 있는가? | ○ / ✗ / ● / - |
| **자동 화질 조정** | 네트워크 속도에 따라 화질이 자동 조정되는가? | ○ / ✗ / ● / - |
| **데이터 절약 모드** | 저용량 스트리밍 옵션이 있는가? (모바일 사용자용) | ○ / ✗ / ● / - |
| **버퍼링 표시** | 로딩 중임을 명확히 표시하는가? (로딩바, 시간 표시) | ○ / ✗ / ● / - |

### 재생 제어

| 항목 | 기획서 확인 | 상태 |
|------|-----------|------|
| **이어보기 동기화** | 스마트폰에서 끝낸 영상을 TV에서 이어볼 때 시간이 자동 동기화되는가? | ○ / ✗ / ● / - |
| **재생 속도 조절** | 0.5x~2x 속도 조절이 가능한가? (교육 콘텐츠에서 중요) | ○ / ✗ / ● / - |
| **북마크/찜하기** | 영상을 저장할 수 있는가? 저장된 목록에서 재진입 가능한가? | ○ / ✗ / ● / - |
| **건너뛰기 버튼** | 오프닝/엔딩, 광고를 건너뛸 수 있는가? 스킵 시간이 정의되어 있는가? | ○ / ✗ / ● / - |
| **키보드/리모컨 조작** | 터치 없이 리모컨으로 모든 재생 제어가 가능한가? | ○ / ✗ / ● / - |

### 콘텐츠 관리

| 항목 | 기획서 확인 | 상태 |
|------|-----------|------|
| **동시시청 제한** | 계정당 동시에 몇 개 장비에서 재생 가능한가? (예: 프리미엄은 4개, 기본은 1개) | ○ / ✗ / ● / - |
| **개인화 추천** | 사용자 시청 기록 기반 추천이 있는가? 끌 수 있는가? | ○ / ✗ / ● / - |
| **나이 등급 필터** | 콘텐츠 연령 등급(전체, 12, 15, 18세 이상)이 정의되어 있는가? | ○ / ✗ / ● / - |
| **부모 통제(Parental Control)** | 미성년자 사용 시 부모 동의나 PIN 확인 절차가 있는가? | ○ / ✗ / ● / - |
| **시청 기록 삭제** | 사용자가 자신의 시청 기록을 선택적으로 삭제할 수 있는가? | ○ / ✗ / ● / - |

### 라이선싱·지역

| 항목 | 기획서 확인 | 상태 |
|------|-----------|------|
| **지역제한(Geo-blocking)** | 특정 국가에서만 재생 가능한 콘텐츠가 있는가? 차단 시 메시지가 명확한가? | ○ / ✗ / ● / - |
| **라이선스 만료 기한** | 라이선스 만료 예정 콘텐츠를 사용자에게 미리 알리는가? | ○ / ✗ / ● / - |
| **오프라인 다운로드** | 외출 중 보기 위해 다운로드 기능이 있는가? 다운로드 유효 기간은? | ○ / ✗ / ● / - |
| **권리사 표시** | 콘텐츠 저작권, 배급사, 제작사 정보가 명확한가? | ○ / ✗ / ● / - |

### 플랫폼별 차이

멀티 플랫폼 서비스(Web, iOS, Android, Smart TV 등)에서 UX가 일관되는가?

| 플랫폼 | 확인 항목 | 상태 |
|--------|----------|------|
| **웹** | 마우스, 키보드 중심 UI (클릭 기반 메뉴) | ✓ / ⚠ / ✗ |
| **모바일(iOS/Android)** | 터치 중심 UI (탭, 스와이프, 핀치) + 시스템 단축키 지원 | ✓ / ⚠ / ✗ |
| **Smart TV/리모컨** | 리모컨 화살표 키 중심 (위/아래/좌/우) + OK 버튼 | ✓ / ⚠ / ✗ |
| **태블릿** | 웹과 모바일 UI의 하이브리드 (가로/세로 모드 대응) | ✓ / ⚠ / ✗ |

각 플랫폼별 기획서가 별도로 있는가? 없으면 통합 기획서에서 플랫폼별 UX 차이를 명시하는가?

## 종합 판정

| 영역 | 필수 항목 수 | 확정 수 | 미확정 수 | 위반 수 | 진행 가능 여부 |
|-----|-----------|--------|---------|--------|--------------|
| 접근성(KWCAG) | | | | | |
| UX(Nielsen) | 10 | | | | |
| 영상 스트리밍 | | | | | |

**진행 가능 여부**:
- ✓ 가능: 미확정 0, 위반 0 → 개발 시작
- ⚠ 조건부: 미확정 있음 → 우선순위별로 구분해 개발 시작 가능  
  (예: 우선 기능은 미확정 항목이 없어야 하고, 추후 기능은 협의 중이어도 가능)
- ✗ 불가: 위반 항목 있음 → 기획 수정 필수

## 용어 정의

- **기획서**: 기획 문서, 요구사항 명세, 와이어프레임, 프로토타입 모두 포함
- **미확정**: 기획서에 명시된 내용이 없는 상태  
  (예: "자막"이라는 단어 자체가 없음)
- **위반**: 기획서에 명시적으로 접근성/UX를 배제하는 내용  
  (예: "텍스트 없이 아이콘만 사용", "새로고침 시 모든 입력값 초기화")

## 체크리스트 사용 흐름

```
1. 기획서 수집 (문서, 와이어프레임, 프로토타입 모두)
   ↓
2. 본 체크리스트로 검수 (각 항목을 기획서 대비)
   ↓
3. 결과 기록 (상태: ○/✗/●/-)
   ↓
4. 미확정 항목 ← 기획자와 협력하여 확정
   ↓
5. 위반 항목 ← 기획 수정 필수
   ↓
6. 모든 항목이 ✓ 또는 - 가 되면 개발 시작
```
