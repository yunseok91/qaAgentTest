테스트 케이스와 커버리지를 작성해 xlsx로 산출한다.

## 0단계: 입력 파일 확인

필수 입력:
- `output/chunks/*.md` — 기획서 원문 (요구사항 근거)
- `output/qa-queries.json` — QA 질의서

선택 입력:
- `docs/qa-query-answered.csv` — 기획자 회신 (있으면 우선 사용)
- 사용자 지정 회신 파일 경로

파일명을 생략하면 `docs/qa-query-answered.csv`를 자동으로 찾는다.
- **찾음**: 그 파일을 회신본으로 사용
- **못 찾음**: qa-queries.json의 QA 권고안을 가정으로 삼아 TC 작성

## 1단계: 테스트 케이스 & 커버리지 작성

qa-designer 에이전트를 사용해 다음을 생성한다:

### 테스트 케이스 (TC)
- **1 TC = 1 검증 목적** (하나에서 여러 개 확인 금지)
- 번호 매긴 절차로 작성 (`1. ` `2. ` 형식)
- 관찰 가능한 동작 명시 (UI 요소 특정)
- 판정 가능한 기대결과 (모호어 금지)
- Priority High 요소에는 예외/경계 케이스 최소 1개 포함

### 커버리지
- 하나의 검증 항목이 여러 TC를 묶음
- 기획자 회신 결과 요약
- 설계서 번호(①②③…)와 연결

### 예외케이스 (탐색적)
- 기획서에 없지만 실무에서 터지는 상황
- 새로고침·뒤로가기, 동시성, 브라우저 호환성, 네트워크 단절 등
- TC가 없으면 스크립트가 "신규 케이스 추가 권장" 표기

### 리스크
- 제품 본질 기준 3개 이내 유형 (R1~R3) 정의
- 왜 이 제품에서 그게 핵심인지 도메인 근거 작성

## 2단계: 최종 보고

완료 후 아래를 보고한다:
- TC 건수 (Priority별: High / Medium / Low)
- 커버리지 항목 수
- 예외케이스 수
- 리스크 유형 수
- **회신 반영 N건 / 가정 기반 N건** (어떤 파일을 회신본으로 읽었는지 경로 포함)

## 3단계: xlsx 생성

qa-design.json을 xlsx로 자동 변환한다:

```bash
python scripts/render_testcases.py output/qa-design.json output/QA_TestCase.xlsx
```

스크립트가 검증(필수 필드, TC 번호 중복, 기대결과 모호어, 커버리지-TC 상호참조)과
xlsx 생성(서식·집계 포함)을 함께 수행한다.

---

**주의**: 
- 기획자 회신본이 다른 경로에 있으면 경로를 지정해야 한다
- xlsx는 반드시 스크립트를 통해 생성한다 (직접 작성 금지)
- 회신이 완전하지 않으면 일부 TC는 가정 기반으로 작성되며, 이는 보고에 명시된다
