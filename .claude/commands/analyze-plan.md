기획서 분석 파이프라인을 처음부터 다시 실행한다.

## 0단계: 대상 파일 결정

- **파일명이 지정된 경우**: `$ARGUMENTS` 경로를 그대로 사용한다.
- **파일명이 생략된 경우**: `docs/` 폴더에서 `.pptx`, `.pdf` 파일을 찾는다.
  - **정확히 1개**: 그 파일을 자동으로 사용하고 어떤 파일을 선택했는지 알린다.
  - **2개 이상**: 목록을 보여줄 때 다음 형식을 따른다:
    ```
    docs/ 폴더에서 여러 파일을 찾았습니다:
    1. proposal-v1.pptx
    2. design-spec.pdf
    
    어느 파일을 분석하시겠습니까? (1 또는 파일명 입력)
    ```
    사용자의 선택을 기다린 뒤, 선택된 파일 경로를 재설정하고 계속 진행한다.
  - **0개**: "docs/ 폴더에 분석할 기획서가 없습니다"라고 안내하고 중단한다.

## 1단계: 이전 산출물 정리

분석 대상 파일명(확장자 제외)의 폴더만 삭제한다. 예: `proposal-v1.pptx` 분석 시 `output/proposal-v1/` 삭제.

다른 문서의 결과물은 건드리지 않는다. 이 방식으로 여러 문서의 분석 결과를 `output/` 아래 각각 유지할 수 있다.

**조건부**: 사용자가 "처음부터 다시" 또는 "새로 분석"이라고 명시적으로 요청할 때만 폴더를 완전히 지운다. 그 외에는 기존 분석 결과를 유지하고 필요한 부분만 업데이트한다.

## 1.5단계: 분석 범위 확인

**슬라이드가 10장 이하면 이 단계를 건너뛰고 2단계로 진행한다.**

슬라이드가 11장 이상일 때:

1. dry-run으로 분류 결과 출력:
   ```bash
   python scripts/extract_doc.py <파일경로> --dry-run
   ```

2. 분석 대상과 제외 항목을 사용자에게 보여준다:
   ```
   분석 대상 19장: 4-11, 13-23
   제외 8장:
     1, 2      개요 (제외어: 개요)
     3, 12     [PC] 글로벌... (명세 표 없음)
     24-27     Appendix (제외어: appendix)
   ```

3. "이 범위로 분석을 진행할까요?" 라고 사용자에게 확인한다.

**사용자의 답변에 따라**:
- **확인 (기본값)**: 2단계로 진행
- **범위 수정**: "--pages" 옵션을 지정받아 2단계에서 다시 실행
  - 예: `--pages 4-11,13-23` 으로 분석 재실행

## 2단계: 기획서 분석

Agent 도구로 planning-analyst 서브에이전트를 직접 호출하여 청크 분석을 수행한다.

**호출 정보**:
- **청크 폴더**: `output/{문서명}/chunks/`
- **manifest**: `output/{문서명}/manifest.json`
- **분석 범위**: 1.5단계에서 확인한 범위 (또는 --pages로 지정한 범위)

**planning-analyst가 수행하는 작업**:
1. 청크 읽기 및 매핑된 카테고리별 검토 (A-01~A-13)
2. 이미지 대조 (manifest의 needs_vision=true 슬라이드)
3. 중복 제거 및 문서 간 충돌 탐지
4. `qa-queries.json` 생성
5. 자동 검증 및 렌더링

자세한 절차는 `.claude/agents/planning-analyst.md` 참조.

## 3단계: 최종 보고

완료 후 아래를 보고한다:
- 분석 대상 파일명
- 처리된 청크 수
- 질의 개수 (우선순위별: 필수/높음/중간)
- 문서 간 충돌 개수
- 접근성(KWCAG) 확인 결과
- `output/{문서명}/` 에 생성된 최종 파일 목록과 각 파일 크기

## 4단계: 완료 확인

planning-analyst가 완료되면 `output/{문서명}/` 폴더에 다음 파일들이 생성되었는지 확인한다:

- ✓ `manifest.json` (분석 메타데이터)
- ✓ `chunks/C001.md`, `chunks/C002.md` 등 (청크 마크다운)
- ✓ `qa-queries.json` (QA 질의서)
- ✓ `qa-query-sheet.md` (질의 마크다운)
- ✓ `qa-query-sheet.csv` (질의 CSV)
- ✓ `partial/` 폴더 (재실행용 중간 파일, 존재하면 유지)

**참고**: md/csv 생성은 planning-analyst의 "검증 및 렌더링" 단계에서 자동 수행된다.

---

**주의**: 이 명령은 매번 1단계부터 실행해서, 이전 실행 결과가 새 결과와 섞이지 않도록 한다.
